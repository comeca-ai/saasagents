Conecte a Mesa dos Agentes ao seu GitHub

Tudo roda no GitHub Actions do seu repositório, sem servidor para contratar. O modelo de IA usa a sua própria chave, guardada nos secrets do repositório: ela nunca passa por esta página nem por nós.

→
GitHub Actionslê README, STATUS, backlog e tickets
→
Modelo de IA com a sua chaveAnthropic, OpenAI ou compatível
→
Comentário na Issuecom modelo, tokens e link da execução
0 de 6 etapas
    1

    Repositório

    pendente

    Informe o repositório que vai receber os agentes. Você precisa de permissão de escrita nele.

    Formato dono/nome. Pode colar o link do GitHub.
    As Issues só disparam o workflow que está nesta branch.
    Abrir repositório
    2

    Agentes e modelo

    pendente

    Cada agente tem um papel e instruções. Na Issue, a linha Agente: id escolhe quem responde; sem ela, responde o primeiro da lista.

    A cobrança de cada tarefa vai para a conta do cliente neste provedor.
    A parte antes de /chat/completions.
    Separados por vírgula. Arquivos .env e chaves nunca são lidos.
    Até 8 arquivos .md desta pasta entram no contexto.
    3

    Instalar os arquivos

    pendente

    São três arquivos no seu repositório. Cada botão abre a tela de novo arquivo do GitHub com o caminho preenchido; revise e clique em Commit changes.

    Arquivo grande demais para o link?Quando o conteúdo não cabe no endereço, o botão copia o texto antes de abrir o GitHub. Cole no editor e faça o commit.
    4

    Salvar a chave do modelo

    pendente

    Gere uma chave no painel do provedor e salve como secret do repositório. O workflow lê o secret na hora de rodar; ninguém mais vê o valor.

    1. No painel do provedor, crie uma chave de API. Abrir o painel de chaves
    2. Abra os secrets do repositório e clique em New repository secret.
    3. Em Name, use exatamente SAASAGENTS_API_KEY. Em Secret, cole a chave e salve.
    Abrir os secrets do repositório
    A chave não passa por aqui.Esta página não pede nem guarda a chave. Ela fica criptografada nos secrets do GitHub e só é entregue ao job do Actions.
    5

    Ativar e testar

    pendente
    1. Abra Actions → Mesa dos Agentes no seu repositório.
    2. Clique em Run workflow e mantenha a ação configurar.
    3. A execução cria a label agente e faz um teste de conexão com o modelo. O resultado aparece no resumo da execução.
    Se o teste falharO resumo da execução diz o motivo e o que fazer: secret ausente, chave recusada, conta sem créditos ou modelo que não existe no provedor.
    Abrir o workflow no Actions
    6

    Primeira tarefa

    pendente

    A tarefa vira uma Issue com a label agente. A resposta chega como comentário em cerca de um minuto.

    Criar a Issue no GitHub
    Continuar a conversa e acompanhar

    Na própria Issue, comente /agente seguido do novo pedido. Para chamar outro agente, use /agente @revisor quais riscos você vê?. Só donos, membros e colaboradores do repositório disparam o agente.

    Issues com a label agente Execuções no Actions

    Custos: cada tarefa é cobrada pelo provedor do modelo na conta do cliente, conforme os tokens usados. O comentário de cada resposta mostra os tokens de entrada e de saída. Os minutos do Actions seguem a cota do repositório. Esta página não estima valores.
